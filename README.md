# Unit Economics Analysis — Pandas + SQL

Комплексный проект по анализу юнит-экономики интернет-магазина: расчёт ключевых
финансовых метрик (Revenue, COGS, Gross Profit, Gross Margin, AOV, Profit Contribution)
на исторических данных о заказах за первые 6 месяцев 2026 года, с двумя параллельными
подходами к расчёту — через **pandas** и через **SQL (SQLite)**.

## Что внутри

- **[`notebooks/unit_economics_analysis.ipynb`](notebooks/unit_economics_analysis.ipynb)**
  — основной ноутбук с полным ходом анализа: от загрузки и первичной проверки данных
  до продвинутых SQL-запросов с подзапросами, EXISTS, CASE WHEN и оконной логикой
  сегментации клиентов.
- **[`docs/SQL_glossary.md`](docs/SQL_glossary.md)** — справочник по SQL-конструкциям,
  собранный в процессе работы над проектом: структура запроса, WHERE vs HAVING, когда
  нужна двойная агрегация через `FROM(SELECT...)`, ALL/ANY, EXISTS, CASE WHEN — с
  разобранными примерами и типичными ошибками.

## Структура анализа

**1. Загрузка и первичный анализ данных**
Проверка структуры трёх исходных таблиц — `orders`, `products`, `customers` — на
пропуски и типы данных.

**2. Расчёт экономики (pandas)**
- Количество заказов и проданных единиц товара за период
- Общая выручка (Revenue = price × (1 − discount) × quantity)
- AOV (Average Order Value) — средняя выручка на один заказ
- COGS, Gross Profit, Gross Margin
- Разбивка метрик по категориям товаров
- Profit Contribution — вклад каждой категории в общую валовую прибыль
- Разбор кейса: почему категория с самой высокой маржой не является лидером
  по абсолютной прибыли (объём продаж и средняя цена как факторы)

**3. EDA**
Визуализация Revenue, Gross Profit и Gross Margin по категориям.

**4. SQL unit-economics queries**
Тот же набор метрик и ещё 15 бизнес-кейсов, реализованных на SQL (SQLite) —
от простых `GROUP BY` до продвинутых конструкций:
- Подзапросы в SELECT / FROM / WHERE / HAVING
- Двухуровневая агрегация (среднее по группам, а не по строкам)
- `ALL` (эмуляция через `MAX()`, так как SQLite не поддерживает `ALL`/`ANY` напрямую)
- Коррелированные подзапросы через `EXISTS`
- `CASE WHEN` для сегментации клиентов (VIP / Regular / Low)

## Стек

- Python 3, pandas, matplotlib
- SQLite3 (через `sqlite3` + `pandas.read_sql_query`)
- Google Colab (среда разработки)

## Данные

Ноутбук ожидает три CSV-файла в рабочей директории Colab (`/content/`):
`orders.csv`, `products.csv`, `customers.csv` — заказы, товары и клиенты интернет-магазина
за период 2026-01-01 – 2026-06-30.

## Как читать ноутбук

Ноутбук отражает реальный процесс обучения и отладки запросов — наравне с финальными
рабочими решениями в нём сохранены промежуточные версии запросов, разбор ошибок и
пояснения (раздел "Ошибки" в конце). Это сделано намеренно: ноутбук служит не только
результатом анализа, но и учебным конспектом по SQL для аналитика.
